# Azure Pillar 1 Deployment

## Prerequisites

- Explicit approval of the approximately USD 393/month fixed staging baseline.
- Azure CLI, Bicep CLI, Docker, Node.js, and PowerShell 7.
- Current authenticated Azure subscription only.
- GitHub staging environment with required reviewers where available.
- OIDC user-assigned identity bootstrapped with deployment permissions for the dedicated staging resource group.

## Required environment variables

Names only are listed here. Values must not be printed.

```text
AZURE_PILLAR1_FIXED_COST_APPROVED
AZURE_APIM_PUBLISHER_EMAIL
SUPABASE_URL
SUPABASE_ANON_KEY
SUPABASE_SERVICE_ROLE_KEY
DATABASE_URL
UPSTASH_REDIS_REST_URL
UPSTASH_REDIS_REST_TOKEN
NEXORA_AUTH_SECRET
POSTHOG_PROJECT_API_KEY
APIM_BACKEND_SHARED_SECRET
```

Runtime variables generated by Bicep include `ENVIRONMENT`, `APP_VERSION`, `GIT_COMMIT_SHA`, `BUILD_TIMESTAMP`, `CORS_ALLOWED_ORIGINS`, `AZURE_CLIENT_ID`, `AZURE_SERVICE_BUS_NAMESPACE`, `AZURE_SERVICE_BUS_QUEUE_NAME`, and `AZURE_STORAGE_ACCOUNT_URL`.

## Validate without provisioning

```powershell
./infra/scripts/validate.ps1
python -m pytest tests/test_pillar1_runtime.py -q
```

## Deploy staging after approval

```powershell
$env:AZURE_PILLAR1_FIXED_COST_APPROVED = "true"
./infra/scripts/deploy-staging.ps1 -ApproveFixedMonthlyCost
```

The script deploys the foundation, pushes SHA-tagged images, deploys workloads and edge resources, feeds the exact Front Door hostname into CORS, and uploads the unchanged frontend to Static Web Apps.

## GitHub OIDC bootstrap

The identities module can create a federated credential for the `staging` GitHub environment. An authorized administrator must grant the deployer identity the minimum repository-specific deployment roles needed to deploy Bicep at the staging resource-group scope. Do not grant Owner.

GitHub environment secrets contain external-service values. Repository variables must include `AZURE_PILLAR1_FIXED_COST_APPROVED=true` only after approval. The workflow never deploys production.

## Smoke test

Use safe outputs from the subscription deployment:

```powershell
./infra/scripts/smoke-test.ps1 `
  -ResourceGroup <staging-rg> `
  -FrontDoorHostname <front-door-host> `
  -ApiContainerAppHostname <api-host> `
  -ApiManagementHostname <apim-host> `
  -WorkerContainerAppName <worker-name>
```

The test uses `pillar1-staging-test/request-flow`, invokes no paid AI model, verifies the queue/worker/blob path, checks correlation, rejects sensitive payloads, and confirms direct API/APIM bypass and worker ingress are blocked.

## Production boundary

Do not change production DNS, stop Render, alter the Nexora resource group, or route customer production traffic to staging. Pillar 1 ends after staging verification and WAF findings review.
